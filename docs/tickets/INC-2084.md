# INC-2084: Results filed to a duplicate patient record

**Reported by:** Health Information Management (HIM)
**Symptom:** Registration created a duplicate MRN (9061) for a patient whose real MRN is 9060. Lab results filed to 9061 were invisible on the real chart. HIM merged the records in the EHR, which sends an **ADT^A40**.

## Analysis
- In an A40, **PID.3 = surviving** identifier, **MRG.1 = retired** identifier.
- Downstream, a merge is an **UPDATE** that re-points records; nothing is deleted.
- Keep the old MRN for audit, late messages and possible unmerge.
- Validate first: empty or identical MRNs must never reach the database (a wrong merge is a patient-safety "overlay").

## Fix
- New column `HL7_LabResults.original_mrn` and table `HL7_PatientMerges` (audit log, `message_id` unique).
- Channel `ADT_A40_Merge`: filter ADT **and** A40; transformer reads and validates PID.3 / MRG.1 / EVN; destination SQL updates results and logs the merge.

## Verification

|---|---|
| HbA1c 7.8 H under MRN **9061** | Same result under MRN **9060**, `original_mrn` = 9061 |
| No merge log | `ADT40001`, 9060 ← 9061, Kwame Darko, merged by Ama Mensah |

Other patients' rows unchanged.
