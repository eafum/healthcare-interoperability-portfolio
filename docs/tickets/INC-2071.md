# INC-2071: Lab comments missing and corrected results duplicated

**Reported by:** Clinic nurse manager
**Symptom:** Lab comments (NTE) from the lab were not stored, and a corrected potassium result created a second row, so the physician saw two values.

## Analysis
- NTE segments belong to the segment **directly before them**; these NTEs followed the Potassium OBX.
- A correction is flagged by **OBX.11 = C** (and OBR.25 = C).
- The same result is identified by **filler order number (OBR.3) + LOINC code (OBX.3)**. MSH.10 changes on every message, so it can't be the key.

## Fix
- Transformer walks **all segments in order** (`msg.children()`), builds one result per OBX and joins following NTE lines into that result's comment.
- Destination (Database Writer, JavaScript mode) loops over the results: `UPDATE … WHERE filler_order = ? AND loinc_code = ?`, and `INSERT` when no row was updated.
- `UNIQUE (filler_order, loinc_code)` in the table as a safety net.
