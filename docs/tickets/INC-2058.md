# INC-2058: Charges feed into the billing table (DFT^P03)

**Reported by:** Patient Financial Services
**Request:** Lab, radiology and pharmacy systems send charges as **DFT^P03** on port 6671. Billing needs every charge stored once in SQL Server, with reversals (credits) linked to the charge they cancel. Resent messages must not double-bill, and messages that are not charges must not be loaded.

## Analysis
- **FT1.2** transaction ID is the unique key for a charge.
- **FT1.6** transaction type: `CG` charge, `CD` credit (reversal).
- **FT1.7** charge code (CDM), **FT1.10** quantity, **FT1.11** amount, **FT1.19** diagnosis (ICD-10), **FT1.25** procedure code (CPT/HCPCS), **FT1.29** NDC for pharmacy charges.
- **ZFT.2** revenue code (custom Z-segment).
- A credit carries the original transaction ID, so it can be linked back to the charge.

## Fix
- Table `DFT_Charges`, one row per transaction ID, with `reference_txn` for credits.
- Channel on MLLP 6671:
  - Source filter: MSH.9.1 = `DFT`.
  - Transformer reads FT1 and ZFT fields.
  - Destination: `IF NOT EXISTS` on the transaction ID, then `INSERT`, so a resend is ignored.

## Test feed
`sample-messages/dft/INC-2058_dft_feed.hl7`:

| Message | Scenario | Result |
|---|---|---|
| DFT40001 | Lab charge, CBC (CPT 85025) | Loaded |
| DFT40002 | Radiology charge, chest X-ray 2 views (CPT 71046) | Loaded |
| DFT40003 | Pharmacy charge, ceftriaxone (HCPCS J0696 + NDC) | Loaded |
| DFT40003 (again) | Same message resent | **Ignored** (no duplicate charge) |
| DFT40004 | Credit (`CD`) reversing TXN90002 | Loaded, `reference_txn` = TXN90002 |
| DFT40005 | Corrected charge, chest X-ray 1 view (CPT 71045) | Loaded |
| ADT50001 | ADT^A08 sent to the charges port by mistake | **Filtered** |

**Result:** 5 rows in `DFT_Charges`, no duplicates, and the credit linked to its original charge.

## Note
The filtered ADT was answered with `AR` by default; the response settings were changed so filtered messages are acknowledged with `AA` and an explanatory text (troubleshooting log #9).
